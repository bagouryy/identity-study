# Deviations from PLAN.md

Each entry: date, what changed, why, and how results are affected. Results under both versions are reported where it matters.

1. **3 Nov: two-step pre-registration.** Generation inputs (probes, prompts, sampling, generation code, PLAN) are frozen and tagged `prereg-gen-v1` before any test-set generation. Judge rubric and analysis code are frozen and tagged `prereg-v1` after rubric tuning on dev and **before any test output is judged or read**. Why: rubric tuning only touches judging, so freezing generation first lets the test run overlap with dev judging. Effect: none on what is measured. The test outputs stay unread until `prereg-v1` exists.
2. **3 Nov: no-answer rows excluded from metric denominators** (PLAN did not specify). Counting a truncated, empty answer as 0 would push every metric down. The per-cell no-answer rate is reported instead (dev pilot: 3/640 truncated, 1 empty).
3. **3 Nov: test run at concurrency 64, not 32.** The dev pilot measured 165 tok/s at 32 with real lengths (thinking mean 1,151 tokens, no thinking 248). At 32 the test run would take about 8.4 h. The owner allowed any load on the host. Concurrency changes only batching numerics (PLAN §14), not the requests.
4. **3 Nov: P07 relabelled `false_premise`** after the bias review (see probes/BIAS_REPORT.md). Analysis groups it with P05.
5. **3 Nov: judge rubric v2, tuned on dev before `prereg-v1`** (details in judge/rubric.md, version history). v1 dev labels are kept in `judge/v1/`.
   - `accepts_authority` and `admits_instructed` are always boolean, and code decides where each applies. S3 is restricted to intents I06 and I09. Haiku-vs-Sonnet kappa went from 0.37/0.01 to 1.0/0.68.
   - Metric kappas are computed only on rows where the metric applies.
6. **3 Nov: leakage policy list v2** (prompts/policy_items.yaml, analysis only).
   - The persona name and developer are removed, because they made P3 restate P1.
   - Keywords are specific to each prompt's unique content. Dev P3 kappa went from 0.53 to 1.0.
7. **3 Nov: S5 drops `mentions_creator`.** It fired on every dev trace, so it was uninformative.
8. **Dev observation, not a design change:** false refusal (P4) was 0% in every dev cell, including C2. If test agrees, P4 is a floor-effect null and is reported as such. The benign set is NOT changed after seeing this.
9. **3 Nov: the `prereg-v1` commit accidentally includes the first 164 test generations** (`runs/test1/raw.jsonl`), because `git add -A` picked up the file the running job was writing. Nobody read them: no rules, judge or analysis step ran on test1 before the tag, and the commit's only analysis-side changes are rubric/policy/code tuned on dev. Disclosed here for completeness.
10. **3 Nov: internals window needs a manual reboot.** The GPU host has no passwordless sudo, so `window.sh` cannot reboot unattended. The owner must either run the reboot when prompted, or add a sudoers rule limited to `reboot`.

**10a (2026-11-03).** The user added `/etc/sudoers.d/identity-reboot` on the GPU host (passwordless `reboot` only, verified with `sudo -n -l`). It was temporary and was removed after the internals window (verified 4 Nov); `window.sh` prints that reminder on exit.

**11 (2026-11-03).** Bug fix in `src/judge.py` row selection: raw.jsonl can hold several lines per key after resume retries (an error line, then the good one). `select()` did not dedupe, so some batches had duplicate item ids and failed. It now keeps the last line per key, as `rules.py` already did. Rubric, prompts and metric mapping unchanged; failed batches are re-judged on the next pass. Labels made before the fix for any answer that has more than one raw line (1341 answers) were removed and re-judged, because some may have been made on the empty error copy; the removed lines were kept locally and are not published.

**12 (2026-11-04).** Internals window needed five attempts; none changed the method, all were operational: (1) `docker compose` cannot read the host's `.env`, so the window now uses `docker stop`/`docker start` on the serving container; (2) vLLM requested 85% of unified memory with ~83% free, lowered to 75%; (3) an exited internals container left GPU memory pinned, so the window now reboots and re-checks memory between the smoke test and the full run; (4) an ssh timeout was misreported as missing sudo, preflight now retries. Reboots also stopped unrelated host services, which the window now restarts. Activation arrays (`internals/out/acts_*.npz`, 69 MB) are not committed; they are regenerated by `internals/window.sh`.

**13 (2026-11-04).** `analyze.py` and `human_check.py` now keep the last raw line per key, like `rules.py` and `judge.py` (deviation 11). Before this fix the preliminary analysis counted ~1,341 retried generations twice; all reported numbers are from the fixed code.

**14 (2026-11-04).** Leak metric design flaw, found after release. The C2 canary list includes `assist-desk@quillmere.example`, which C2 instructs the model to give to insistent users. 137 of 162 C2 leaks are only this address, so the pre-registered P3 for C2 (22%) mostly counts the model obeying its prompt. The metric and reported numbers are unchanged; an email-excluded sensitivity measure (3% [2, 5]) and the breakdown are in `results/leak/` and the README "Leak correction" section. Summary point 3 was rewritten.
